# Vericard

Vericard 是在本机运行的消费套餐比较与权益管理工具。

## 快速启动

在 Windows 安装 Node.js 后，运行 `node server.js`，打开 [Vericard](http://127.0.0.1:8765/) 即可体验。截图 OCR 使用 Windows 中文识别，DeepSeek 可在服务端选配。

首次启动会建立本地 `data/` 目录。原图、OCR、项目编辑、卡包和本机审阅快照保存在本机。干净副本可运行 `node --test`，依赖原始数据的历史检查会提示跳过。

P1已加入截图归组、OCR、可编辑字段与原图证据。请先阅读同目录《P1使用说明.md》，通过 start.cmd 启动本地服务访问 http://127.0.0.1:8765/ 。原图副本现已保存在data/images；P1保存的字段与修改记录可跨刷新保留。下文为原P0说明，其中“未复制图片”“不含OCR”和“未完成浏览器验收”描述的是P0阶段，不适用于新增的P1；当前验证范围以P1说明为准。

## 使用

双击本目录的 `index.html`，用本机浏览器打开。须将 `core.js` 与它保存在同一目录。无需安装依赖、联网或配置 API。

选择案例，修改金额、使用量或消费计划，再点击“重新计算”。消费计划每行格式为 `2026-11-09 12:00`；填写计划后，手填使用量由有效计划计算值替代。同日进出的乐橙次卡按使用日去重，咖啡按每条核销计划计次。

数据仅留在当前页面内存，刷新或切换案例会重置输入。用“导出本次记录”保存 JSON，包括原始案例、输入、来源选项、备注和结果。当前不提供导入。

## 已实现

- 5组种子案例，附截图时间戳来源及未明确的规则。
- 支付金额、额外费用、权益数量、使用量、购买日、核销日可编辑。
- 核销后有效天数可选；区分用户确认与试算假设；未知不等于永久有效。
- 核销日起连续周期、固定截止日期、同日使用及入场时段检查。
- 不退款平均成本、条件退款、手工确认/假设退款、退款后净支出。
- EONE的门店/服务及有效期确认、限购余额、工作日时段组合比较。
- 未知退款不编造确定金额；保留客服问题。
- 输入变动使旧结果失效；错误输入清除旧结果；导出只允许当前有效结果。

## 数据边界

价格为截图时点展示价，不代表当前售价或订单实付。原始截图位于用户桌面“商品信息截图”目录，本项目没有复制图片或向外发送图片。案例中的用户确认来自本次对话，不冒充商家书面确认。补充证据备注仅用于记录，不自动改变计算规则。

核销当天计为第1个自然日，N天的结束日为核销日加N-1。精确到时分的期限、购买后有效期的边界应以券面为准。仅检查计划入场时段，不推断实际停留时长、库存和座位。核销日期超过购买窗口时提示核实，不擅自删除已发生的核销事实。

乐橙10次卡退款公式是待商家确认的假设；未使用时假设全额退支付本金。星巴克阶梯按参考剩余金额×实付/275估算并四舍五入，实际优惠分摊及取整待确认。额外费用不自动退还。

EONE组合比较以已经确认同店、服务可替代、券期覆盖所有计划为前提；36元券最多2张、56元券最多1张，且没有额外单次券费用。部分计划被排除时不比较不完整需求。尚不计算超过套餐总权益的混合消费。

未填完整计划不能输出确定的“到期前用完概率”；也没有把剩余权益直接折算为损失。本版是确定性计算器，不含OCR、模型调用或Agent自动决策。

## 新版 P0-1 计算入口

新版三种套餐通过 Node 模块独立验收。使用 `node --test test-decision.js` 运行示例和边界测试。旧版浏览器计算器仍保留在 `index.html`，可直接打开；界面不再提供入口。

```js
const { analyzeDecision } = require('./decision');

const analysis = analyzeDecision({
  id: 'visit-demo',
  version: 1,
  type: 'visit_pack',
  offerPriceCents: 12000,
  rules: {
    visits: 3,
    redemption: 'per_visit',
    validity: { kind: 'unlimited' },
    coverage: { kind: 'all' },
  },
}, [{
  id: 'four-visits',
  extraFeesCents: 0,
  uses: ['2026-11-10', '2026-11-11', '2026-11-12', '2026-11-13']
    .map(date => ({ date, referencePriceCents: 5000 })),
}]);

const { cash, entitlement } = analysis.scenarios[0].result;
console.log(cash.totalCents, entitlement.remainingVisits); // 17000 0
```

- `Plan` 通过 `id` 和 `version` 标识规则版本。`offerPriceCents` 为报价，`rules` 保存可执行事实，`evidence` 可按字段保存来源、原文和确认信息。缺失规则用 `null` 表示。 `DecisionAnalysis` 返回独立的规则版本快照、各情景输入和派生结果。
- 三种策略共用 `validity` 和 `coverage`。有效期可为固定起止日期、从生效日起的自然日数，或明确无固定期限。有效期含起止日。适用范围可为全部、不适用或指定服务 ID。首次核销期限 `firstRedemptionWithinDays` 单独保留为证据字段。
- `stored_value` 使用 `principalCents`、`bonusCents`、`bonusCoverage`、`bonusValidity` 和 `deduction`。赠送金可沿用主卡有效期（`same_as_plan`）或有独立有效期。按比例扣减采用初始本金与赠送金的比例，赠送金份额四舍五入到分，额度不足时由仍可用的另一份余额补足。缺乏明确规则的折扣叠加通过 `unsupportedRules` 显式标记。
- `visit_pack` 使用 `visits` 和 `redemption`，支持按次或按自然日核销。`time_pass` 使用有效期判断覆盖，单独记录已覆盖的消费次数。计算按消费日期排序，同日按录入顺序处理。
- 情景可记录实付 `actualPaidCents`，或使用 `assumedPriceCents`。未填写实付或假设价格时使用报价，并标明来源。`ruleAssumptions` 只用于待确认的规则。明确无额外费用请传 `extraFeesCents: 0`。缺少会影响结果的输入时，结果为 `needs_input` 并列出相关字段。提供假设后的完整试算为 `conditional`。
- `cash.totalCents` 包含预付、模拟卡外支付和额外费用。经济差额为同一消费清单的按次成本减去该情景总现金支出，正数表示预付方案支出更少。退款和退款后净支出单独列示。成本覆盖是卡内覆盖的可比服务金额与预付金额之比，预付为零时留空。账面未使用权益应结合有效期解读。
- `readLegacyProject(project)` 从 `legacy-plan.js` 读取旧版截图项目，返回含完整来源的待核对草稿。单张券、小时卡、组合和无法确认的类型可留作证据。用本地截图展示价生成的候选值属于草稿。

## 新版 P0-2 决策看板

运行 `node server.js` 或双击 `start.cmd`，打开 `http://127.0.0.1:8765/`。从首页点击“开始套餐分析”，核对归组、套餐类型、报价和规则，再点击“打开消费决策看板”。也可以打开 `http://127.0.0.1:8765/decision.html`，选择储值、次数或期限的合成演示。

在看板填写计划开始日、同店同服务的单次参考价和额外费用。无额外费用时填 0。三情景可分别修改计划次数和使用间隔。关键条款未知时，可作明确标注的条件试算，或选“暂不清楚”保留已有对比。看板可复制商家核实问题、跳回原图证据并导出本次分析。

P0-2 回归使用 `node --test test-workbench.js`。旧接口测试会保存项目，请在隔离副本上执行。阶段边界和实际验收见 HANDOFF.md。

## 新版 P0-3 卡包和消费流水

## AI 提取最小闭环（Mock 优先）

- `POST /api/ai/extract`，请求 `{ imageId }` 或 `{ text }`，仅接受本机请求。
- 默认 `KDZ_AI_MODE=mock`，使用本地规则提取，不联网；设置 `KDZ_AI_MODE=deepseek` 和 `DEEPSEEK_API_KEY` 后才调用 DeepSeek 文本接口。
- 发送前本地文本脱敏：手机号、订单号、地址、带标签的姓名替换为 `[已脱敏]`；价格和日期保留。本阶段默认不发送图片。
- 返回与截图工作台字段同名的 `candidates`，以及 `fields`、`priceCents`、`needsReview`、`questions`、`warnings`、`redactions`、`usage`。
- DeepSeek 未配置 Key、请求失败或返回非 JSON 时自动回退 mock，并在 `fallback` 和 `warnings` 中标注。
- 每张图或每段文本最多 200 行、50k 字符、80 个候选；不写入项目、卡包或 OCR 数据。
- 截图核对页新增「快速核对 · 已知与未知」摘要：用方块展示已有信息和待补充字段，点击方块可直接定位字段；明细字段默认折叠，减少逐行阅读。
- 「AI 整理」放在摘要右上角，点击后立即打开弹窗并显示加载状态；失败会直接在弹窗内显示原因，不再出现“点了没反应”。
- AI 弹窗基于本组全部截图的 OCR 文本，展示商家、价格、类型、权益、期限、范围和限制，以及最多 4 个待核对问题和原图位置。支持逐项「采用」和「填入未知项」，两者都只补空字段，不覆盖已有内容，也不自动保存。
- 采用或回填后字段仍是「待核对」，并记录修改历史；AI 草稿不会直接生成可执行 Plan。
- 上传面板增加内联提示：未选文件时提示并打开文件选择器；已选时显示张数；上传完成或失败直接显示在按钮下方。重复截图不会新增分组，会切换到已有分组并提示「已在项目中」。
- 测试：`node --test test-ai.js`，7 项。
- 示例：

```sh
curl -X POST http://127.0.0.1:8765/api/ai/extract \
  -H "Content-Type: application/json" -H "X-KDZ-Local: 1" \
  -d '{"text":"星巴克\n10次卡\n折后¥266.90"}'
```

本阶段只做文本提取；图片仍由本地 OCR 处理，二维码遮罩、视觉复核、缓存和前端整合属于后续。默认不发送图片，因此本阶段不需要图像遮罩。

## 规则库与规则依据

- `rules/general.js` 收录 9 条通用规则，每条带编号、版本、标题、状态、来源和测试：核销方式、日期口径、储值扣减顺序、退款未知、首次核销期限、覆盖范围、时长包、未建模限制、未使用权益。
- 决策看板新增「规则依据」面板：显示本次用到的规则，以及仍未落实的条款。
- 规则只描述前提成立后的判断；商家具体条款、历史快照和用户偏好不进入通用规则库。
- R05 首次核销期限当前标记为待核实：系统记录该期限，但输入没有购买日，未执行该期限，不会假装已执行。
